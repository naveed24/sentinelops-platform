# Reproducible dashboard builds

The dashboard uses Node.js 22 in CI and a committed npm v3 lockfile generated by npm during a GitHub Actions installation. It contains resolved transitive dependencies and registry integrity hashes; it was not assembled by hand.

CI executes `npm ci --no-audit --no-fund` with npm's dependency cache before Vitest and the typechecked Vite production build. `npm ci` fails if `web/package.json` and `web/package-lock.json` disagree and never rewrites the lockfile.

For local development:

```bash
cd web
npm ci
npm test
npm run build
```

When intentionally updating packages, use `npm install` with a trusted registry to regenerate `web/package-lock.json`; review both manifest and lockfile together in the pull request. CI must pass `npm ci`, tests, and the build on the proposed commit before merging.

The npm cache accelerates downloads but is not a source of truth: integrity verification and version resolution are defined by the committed lockfile. Build artifacts remain available for seven days. A lockfile improves repeatability but does not guarantee that packages are free of vulnerabilities.
